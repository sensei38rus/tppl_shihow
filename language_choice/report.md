# 1. Обработка больших данных в реальном времени

**Парадигма:** Объектно-ориентированное программирование (ООП) с элементами параллельного/обобщенного программирования (Multithreading & Generic Programming)  
**Язык программирования:** C++ (стандарты C++17/C++20)

### Обоснование

* **Высокая производительность и пропускная способность:** Поток 100 кадров/с при разрешении 4096×4096 (16 бит/пиксель) генерирует поток данных около **3.2 ГБ/с** ($4096 \times 4096 \times 2 \text{ байта} \times 100 \text{ кадров}$). C++ предоставляет прямой доступ к памяти и управление ресурсами, что критично для обработки таких объемов без задержек.
* **Отсутствие Overhead (Garbage Collector):** Использование языков с автоматической сборкой мусора (Java, C#, Go) приведет к непредсказуемым паузам (Stop-the-World), что недопустимо при режиме 24/7 и фиксированной частоте кадров. В C++ управление памятью детерминировано (RAII, smart pointers).
* **Аппаратное ускорение и SIMD:** C++ легко интегрируется с SIMD-инструкциями процессора (AVX-512) и фреймворками для параллельных вычислений на GPU (CUDA, OpenCL, Vulkan), что позволяет выполнять математический анализ изображений на высокой скорости.
* **Надежность 24/7:** Строгая статическая типизация и концепция RAII предотвращают утечки памяти и ресурсов при длительной непрерывной работе.

# 2. Прототип ML-сервиса для прогноза погодных условий

**Парадигма:** Мультипарадигменный подход (Императивное + Функциональное + ООП)  
**Язык программирования:** Python

### Обоснование

* **Скорость разработки (MVP за 2 недели):** Python обладает лаконичным синтаксисом и наименьшим объемом шаблонного кода (boilerplate), что позволяет запустить работающий прототип в кратчайшие сроки.
* **Экосистема ML и DS:** Python является стандартом de facto в области машинного обучения. Он предоставляет готовые зрелые библиотеки (`scikit-learn`, `XGBoost`, `Pandas`, `NumPy`, `Prophet`), оптимизированные на уровне C/C++.
* **Гибкость и быстрые итерации:** Динамическая типизация и скриптовая природа языка позволяют мгновенно менять алгоритмы, экспериментировать с признаками (feature engineering) и гиперпараметрами.
* **Низкая частота вычислений (1 раз в сутки):** Поскольку задача не требует работы в жестком real-time, производительность самого интерпретатора Python не является узким местом.

# 3. Интерактивный UI для торгового терминала

**Парадигма:** Компонентно-ориентированное программирование + Реактивное программирование (FRP)  
**Язык программирования:** TypeScript

### Обоснование

* **Реактивность и сложное состояние:** Интерактивный терминал с 50+ виджетами требует декларативного управления состоянием. Комбинация TypeScript с UI-библиотеками (React, Svelte) и реактивными менеджерами состояния (MobX, Zustand, RxJS) позволяет эффективно обрабатывать потоки данных WebSocket/REST и каскадно обновлять связанные виджеты.
* **Мгновенный отклик (< 16 мс / 60 FPS):** TypeScript компилируется в JavaScript и исполняется современными V8-движками. В сочетании с виртуализацией списков/виджетов и Web Workers (для выноса тяжелых вычислений из основного UI-потока) обеспечивается плавный FPS.
* **Предсказуемость и масштабируемость:** Строгая статическая типизация в TypeScript защищает от ошибок во время выполнения (`undefined is not a function`), что крайне важно при передаче финансовых данных из разных источников.
* **Тестируемость:** Компонентный подход и чистые функции в реактивных архитектурах позволяют легко покрывать код Unit-тестами (Jest, Vitest), тестами компонентов (Testing Library) и E2E-тестами (Playwright).

# 4. Прошивка для устройства регистрации температуры

**Парадигма:** Процедурное / Модульное программирование (с безопасной абстракцией аппаратного уровня)  
**Язык программирования:** C (C11 / C99) *(Альтернатива: Embedded Rust)*

### Обоснование

* **Жесткие ограничения по ресурсам:** Микроконтроллер с 256KB Flash и 32KB RAM сильно ограничен в памяти. Язык C генерирует минимальный размер бинарного кода без накладных расходов на runtime, виртуальные таблицы или сборку мусора.
* **Прямой доступ к железу:** C позволяет напрямую работать с адресами памяти и регистрами периферии (GPIO, ADC, UART) через указатели и структуры волатильных типов (`volatile struct`).
* **Детерминированность (Real-Time):** Время выполнения инструкций предсказуемо и детерминировано. В сочетании с простой RTOS (например, FreeRTOS) или архитектурой Super-Loop обеспечивается гарантированный отклик на прерывания от датчиков.
* **Энергоэффективность:** Предсказуемое управление питанием позволяет быстро переводить МК в глубокие спящие режимы (Deep Sleep) и просыпаться по таймеру/прерыванию, минимизируя расход батареи.
* **Переносимость:** Использование уровня абстракции от аппаратного обеспечения (HAL / Drivers LL) позволяет писать аппаратный код отдельно от бизнес-логики, что обеспечивает легкий перенос прошивки на другие семейства МК (STM32, ESP32, nRF52).
